## Historical Track 3 failures

The 40 historical failed Track 3 sync runs were not silently ignored. They map to these repair classes:

1. Observation CSV schema drift caused csv.DictWriter to reject newly added task fields.
2. Module 1 validation used brittle numerical/source-invariant checks.
3. The Track 3 workflow did not trigger when its validator changed.
4. observation_queue.json lacked count fields expected by the workflow validator.
5. The generated site-domain set omitted schema-defined regulatory and independent_corroboration domains.
6. Evidence-count validation initially omitted power and cooling observation records.
7. Concurrent sync runs could race while pushing generated snapshots.
8. data/module1_radar_summary.json was refreshed but initially omitted from the generated-artifact commit.
9. The canonical Track 3 validator later exposed an evidence-accounting mismatch; the validator was corrected and Run 110 passed.
10. The next generated snapshot/commit cycle was validated by Run 111.

Important: the presence of a historical failed run does not mean the current pipeline is failing. Current operational state is determined from the latest run and the generated artifacts it committed.

## Interpretation

The repository is an independent research implementation. It is not an AI Futures Project publication, does not speak for AI 2040, and does not certify a treaty or verification regime.

The audit deliberately keeps three questions separate:

1. Does the Track 3 generated data pipeline pass?
2. Does the public site build/deploy?
3. Does the repository accurately expose the AI 2040 Plan A / Track 3 mapping?

All three are independently tested. Track 3 itself is not complete: the public mapping marks several requirements as PARTIAL or DESIGN_ONLY, and the missing evidence streams remain explicit rather than being converted into claims of absence.
